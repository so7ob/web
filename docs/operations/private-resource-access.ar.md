# حدود الوصول إلى الموارد الخاصة

W03b/Issue #16 وجزء صلاحيات #8. تُفحص صلاحية الاستفسار قبل قراءة مرفقه: المالك أو inquiries.view.all؛ رافع المرفق لا يحل محل ملكية الاستفسار. المرفق بلا مورد لا يصل إليه إلا رافعه. يبقى Cache-Control private/no-store والتقديم attachment. الموقوف مرفوض.

سياسة الصفحة موحدة في metadata والعرض: public للجميع، authenticated لصاحب جلسة غير موقوف، role للأدوار المصرّح بها فقط، مع استثناء super_admin الصريح الموجود سابقًا. يُرفض JSON أدوار تالف أو visibility غير معروفة لغير مدير النظام. لا تعود تسمية الموظف وحدها تصريحًا عامًا. metadata غير المسموح بها لا تشمل عنوانًا/وصفًا خاصًا، بل noindex/nofollow فقط. سياسة مشتركة أخرى للمسودات والنشر مستقلة في W05.

admin.dashboard يتيح دخول اللوحة فقط. كل قسم يحتاج صلاحيته: users.view وrequests.view.all وinquiries.view.all وpages.view وaudit.view. لا تُنفَّذ استعلامات الأقسام غير المرخصة؛ API يعيد null لمؤشر غير مصرح ومصفوفة فارغة لقائمته، وSSR يخفي القسم ولا يعرض صفرًا كأنه قياس. super_admin يرى أقسامه السابقة؛ محرر المحتوى يرى بطاقات الصفحات.

لا migration أو تغيير أدوار/ملكية مخزنة. لا تعدّل role permissions لإعادة عرض قسم اختفى إلا بقرار صلاحيات مقصود. التراجع يجب أن يحافظ على سياسات الوصول، لا إعادة bypass العام.

التحقق: اختبارات سياسة للأدوار النظامية والموقوف، اختبارات handlers للمرفق والmetadata واللوحة، وفحص Chromium بعربية RTL وإنجليزية LTR وعلى 375/1280. لقطات ونتائج مصطنعة في docs/verification/16، لا بيانات عملاء. هذه ليست شهادة WCAG أو اختبارًا شاملًا لكل endpoint.
