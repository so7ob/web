# التحقق من المرفقات والوسائط

W03c/Issue #18، جزء من #8. الرفع لا يثق MIME أو الاسم وحدهما. الصور العامة محصورة في JPEG/PNG/WebP/GIF؛ يتم التحقق من decoder sharp الموجود فعلًا وقراءة بيانات الصورة، مع حد 16 مليون بكسل و100 إطار. حجم الملف يبقى 8MiB للوسائط و5MiB للمرفقات. الامتداد يطابق النوع (jpg/jpeg بديلان)، وMIME النص يدعم charset.

يُرفض SVG الجديد، وAPI العام يرفض SVG مخزنًا سابقًا قبل قراءة ملفه. لا تُحذف أي بيانات أو ملفات، ولا يُحوّل SVG تلقائيًا. قبل إطلاق الحظر اجرد SVG في البيئة الخاصة، وخذ backup محميًا وفق #11، وراجع الصور المتأثرة وأنشئ بدائل PNG/WebP معتمدة ثم حدّث المحتوى بالمحرر. يبقى منع SVG فعالًا أثناء المعالجة؛ لا تستعد تقديمه inline عند التراجع. cached responses السابقة قد تبقى حتى انتهاء max-age القديم (ساعة)؛ عند وجود CDN فعلي امسح مساراتها عند الإطلاق. إعداد CDN الفعلي غير متحقق.

المرفقات النصية تتطلب UTF-8 بلا محارف تحكم ثنائية؛ PDF له توقيع وخاتمة. DOC/XLS يُفحص توقيع الحاوية OLE، وZIP فهرسها المركزي المحدود دون فك ضغط، وDOCX/XLSX أسماء المكونات الأساسية في الفهرس. **هذه فحوص نوع وحاوية وليست تحققًا دلاليًا كاملًا للمستند أو فحصًا للماكرو/البرمجيات الخبيثة.** تبقى المستندات تنزيلًا خاصًا مع attachment وnosniff؛ لا تُعرض inline أو يُستخرج أرشيف داخل الخادم. ZIP64 والأرشيف متعدد الأقراص أو أكثر من1000 إدخال غير مدعوم بهذه السياسة. الملفات بترميز نص آخر تحتاج تحويلًا إلى UTF-8 قبل الرفع.

لا حزم جديدة ولا تغيير lock/schema. اختبارات صور ومرفقات مصطنعة وSVG قديم وتزوير MIME وحدود الحجم والبكسلات. حد الجسم قبل multipart parsing ما زال يتطلب ضبط reverse proxy ومراجعة W07؛ فحص الحجم هنا بعد formData لا يحد بمفرده ذاكرة تلقي الطلب. sharp المثبت 0.34.5؛ تحديثه الأمني ضمن W06 ضروري، وليس ادعاء أن التحقق يلغي تنبيهات decoder.
