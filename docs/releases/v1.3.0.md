# v1.3.0 — إدارة موحدة وسير عمل وهوية بصرية

إصدار ميزات بعد [v1.2.1](https://github.com/so7ob/web/releases/tag/v1.2.1)، بطلب المالك في [Issue #96](https://github.com/so7ob/web/issues/96). يرقّي العمل المقبول على `develop` إلى `main` مع حفظ استقلال المستودع والعربية والإنجليزية والصلاحيات والروابط والبيانات. إصدار GitHub مستقل عن نشر التطبيق وترحيل بيانات الإنتاج.

## التغييرات

- [إدارة الهوية](../migration/identity-management-84.ar.md): إنشاء حساب مباشر، وإدارة المستخدمين والأدوار والصلاحيات والتفويض والدعوات والجلسات، مع حماية حسابات الإدارة وبيانات دخول مؤقتة وتغيير إلزامي لكلمة المرور. تبقى hashes bcrypt القديمة متوافقة. [PR #85](https://github.com/so7ob/web/pull/85).
- [سير العمل والمحادثات](../migration/workflows-86.md): إصدارات ثابتة، وفرق مستقلة عن الأدوار، وتقويم ومهل عمل، وطوابير ومراحل ومشغّلات للعامل. نقل المحادثات القائمة يمر بمعاينة وإعادة تحقق صريحة؛ نشر سير جديد يؤثر في المحادثات الجديدة. [PR #87](https://github.com/so7ob/web/pull/87).
- [محرر القوائم](../migration/menus-88.md): ترتيب بلوحة المفاتيح، ومعاينة، ومسودات وحفظ مستقل، مع الاحتفاظ بالمدخلات عند الفشل والتعارض. [PR #89](https://github.com/so7ob/web/pull/89).
- [الإعدادات والمظهر](../migration/settings-90.md): هوية وأصول وألوان وخطوط ومظهر فاتح/داكن/نظام، ومعاينة معزولة وأقسام بحفظ مستقل وصلاحيات خادمية. [PR #91](https://github.com/so7ob/web/pull/91).
- [نظام التصميم](../migration/design-system-92.md): توحيد الموقع العام وحساب العميل والإدارة والمحرر، وتفاصيل الاستجابة والتباين والتركيز وRTL/LTR. تحفظ [أدلة التصميم الاصطناعية](../migration/evidence/design-system-92/README.md) مصدر كل لقطة وحدودها. [PR #93](https://github.com/so7ob/web/pull/93).
- [جاهزية بدء التشغيل](../migration/startup-readiness-82.md): رسائل STARTING وREADY بعد التحقق من المخطط والاستماع الفعلي، مع تشخيص فشل منقح. [PR #83](https://github.com/so7ob/web/pull/83).
- [متانة المعاملات](../migration/transaction-cleanup-94.md): تحرير runner عند فشل الاتصال أو بدء المعاملة، وعدم استبدال سبب الفشل الأصلي بأخطاء التنظيف. [PR #95](https://github.com/so7ob/web/pull/95).
- حماية مدخلات المصادقة واختيار المظهر قبل hydration، وتسلسل حفظ مسودة الطلب قبل حذفها بعد الإنشاء، مع حفظ سلوك الفشل غير المؤكد دون إعادة إرسال تلقائية.

## الترقية من v1.2.1

المتطلبات ثابتة: **Node 24.21.0، npm 10.8.2، MariaDB 10.11.18**. استخدم `npm ci` والقفل المرفق. رقم الجذر `1.3.0`؛ لا تغيّر تحضيرات الإصدار إصدارات workspaces أو الاعتماديات.

يوجد ترحيلان جديدان منذ v1.2.1، بالترتيب المسجل في `createDataSource()`:

| الترحيل | الأثر والتوافق |
| --- | --- |
| `1792022400000-identity-management.ts` | حالة وإصدار وحدود تفويض للأدوار، وحالة بيانات الدخول للمستخدم، وإلغاء الدعوات، وفهرس فريد للبريد بعد `LOWER(TRIM(email))`. تتوقف العملية عند تصادم حسابات قديمة للمصالحة الصريحة؛ لا دمج أو حذف تلقائي. لا تمنح صلاحيات الإدارة الجديدة للأدوار المفوضة تلقائيًا. |
| `1792108800000-workflows.ts` | جداول الفرق والتقويم وإصدارات سير العمل والمحادثات والأحداث والمهام والنقل. تُربط المحادثات القائمة بسير legacy يحفظ حالاتها؛ لا يُفرض تقويم أو سير مخصص على السجلات القائمة. |

في أي ترقية تشغيلية منفصلة ومعتمدة: أوقف الكتابات والعامل أولًا، وخذ النسخة الموثقة من قاعدة البيانات والملفات، ثم جهّز الكود المتوافق وشغّل `npm run db:migrate` و`npm run db:check` بالإعدادات المقصودة. أبقِ الكتابات موقوفة إذا توقفت DDL أو ظهرت تصادمات بريد. تحقق من مخطط الإصدار و`/api/health/ready` وعمل العامل قبل إعادة فتح الكتابات. لا تُنفّذ هذه الخطوات على الإنتاج ضمن إصدار GitHub.

احتفظ بـ`DATA_DIR` والأسرار والملفات وقاعدة البيانات خارج شجرة الإصدار. لا تشغّل `site:init` أو seeds على موقع قائم. لا ترسل أسرارًا أو ملفات عملاء أو dumps في Git أو release assets.

راجع منح الصلاحيات الجديدة قبل التفويض. الفرق ليست أدوارًا. اضبط ساعات العمل والعطلات والمنطقة الزمنية قبل نشر سير مخصص؛ لا توجد ساعات عمل مفترضة. تبقى بيانات الدخول والتحقق من البريد والموافقة التشغيلية حالات مستقلة. `queued` يؤكد إدراج مهمة البريد، ولا يثبت وصولها إلى مستلم خارجي.

## التحقق والأدلة

قاعدة المنتج عند التحضير هي `develop@513eef7428913f3f65b623d81a981c16d3005c15`. فحوص [PR #95](https://github.com/so7ob/web/pull/95) نجحت على `667be814d64fd7e8c11f84dd7dfa442087874ad5`: **958** اختبار وحدة/تكامل و**290** اختبار متصفح، مع lint وtypecheck وbuild والاستقلال والبنية التحتية والترقية والاستعادة والعامل. شجرة ذلك المصدر مطابقة لقاعدة التحضير، لكن نتيجة تشغيله لا تُنسب إلى SHA آخر.

تحضير النسخة يضيف الوثائق ورقم النسخة فقط. نتائج تحضير الإصدار وPR الترقية وSHA `main` النهائي تسجل في [متابعة الإصدار #96](https://github.com/so7ob/web/issues/96) وفحوص PRs والإصدار المنشور، ولا يُستنتج نجاح تشغيل معلق. [سجل التحضير وحدوده](../migration/release-96.md).

الفحوص الكاملة تبقى مفعلة: ESLint مستقل، وTypeScript، وMariaDB اصطناعية معزولة، والوحدة والتكامل، والبناء، واستقلال التشغيل والصيانة، وترحيلات الترقية والاستعادة والعامل، وAR/EN × RTL/LTR × 375/1280 × الفاتح/الداكن، ولوحة المفاتيح وaxe، و`git diff --check`. الصور آتية من تشغيل اصطناعي فعلي؛ تواريخ ومصادر اللقطات السابقة تبقى كما هي، ولا تمثل حسابات عملاء أو إثبات نشر.

نجاح الإصدار لا يثبت نشر التطبيق، أو ترحيل الإنتاج، أو التسليم عبر SMTP خارجي، أو التعافي بعد فقد مضيف مستقل. لا يغير التحضير الحماية أو قواعد GitHub، ولا يتضمن ترقية اعتماديات أو ادعاء تدقيق أمني شامل.

## التراجع

التراجع عبر PR و`git revert`، دون إعادة كتابة تاريخ أو tags منشورة. ترحيلا الهوية وسير العمل يرفضان `down` الهدام؛ احفظ حالات بيانات الدخول والتفويض وتاريخ سير العمل، وتعافَ للأمام بعد عودة الكتابات. لا تستعد قاعدة قديمة فوق كتابات أحدث، ولا تشغّل كودًا أقدم قبل التحقق من توافقه مع بيانات الدخول والسير المخصص وحماية ملفات الهوية. إعادة بناء نسخة أقدم وحدها ليست خطة تراجع آمنة للبيانات.

## English summary

v1.3.0 adds account/role/delegation administration, versioned conversation workflows and teams, business calendars/deadlines, independent menu/settings drafts, site identity and appearance controls, and a shared bilingual design system. It also includes guarded pre-hydration controls, visible startup readiness and transaction lifecycle cleanup.

Upgrade from v1.2.1 includes the explicit identity-management and workflow migrations listed above. Preserve existing bcrypt hashes, reconcile normalized-email collisions without merging accounts, review delegation/workflow grants, and configure a business calendar before custom workflow publication. Existing conversations retain legacy behavior; transferring them requires a reviewed server preview. Keep writers paused during any separately authorized operational migration, verify schema/readiness and the worker, and recover forward after writes resume. This GitHub release does not deploy the application or migrate production data.
