# v1.2.0 — التحقيق والتدقيق وموثوقية العمليات

إصدار كود وتوثيق يجمع تغييرات `develop` منذ [v1.1.0](https://github.com/so7ob/web/releases/tag/v1.1.0). نشر الإصدار على GitHub لا يعني نشر التطبيق أو تنفيذ ترحيل بيانات إنتاج.

## أبرز الإضافات

### سجل التدقيق

- مساحة عربية/إنجليزية للتحقيق: بحث وفلاتر وإحصاءات كاملة، هوية تاريخية ومورد صريح ونتيجة، مقارنة قبل/بعد، تفاصيل مترابطة وعروض شخصية.
- حفظ تغيير الأعمال وحدث نجاحه ضمن المعاملة نفسها، وتنقيح البيانات عند الكتابة والقراءة والتصدير، مع بقاء السجل التاريخي الناقص `unknown`.
- تقارير CSV/JSON/HTML عبر العامل بلقطة MariaDB متسقة، وعدد وبصمة تحقق، وصلاحية تنزيل تُراجع عند الطلب والتنفيذ والتنزيل.
- مراجعات وقضايا وملاحظات مستقلة عن الأدلة، وقواعد تنبيه حتمية وصحة تشغيلية وسياسة احتفاظ اختيارية ومنع حذف للأدلة المحمية.
- توافق المقارنات عند اختلاف collation بين جداول الأدلة والمتابعة، دون تحويل جداول المستخدم.

### الأخطاء والطلبات وحفظ العمل

- تشخيص منقح مرتبط بمعرفات طلب/خطأ، وصلاحيات مستقلة لعرضه ومراجعته.
- استعادة تغيير حالة الطلب وأولويته، والتحقق من الحقول المرسلة دون تحويل حقل غائب إلى عملية أخرى.
- الاحتفاظ بالردود والملاحظات والمدخلات عند الفشل، وحماية النص الذي كُتب أثناء إرسال سابق.
- رسائل مصادقة واستعادة كلمة مرور ومطالبات حساب لا تعرض نجاحًا قبل تأكيد الخادم؛ حفظ حالة الإلغاء والإشعارات عند التعثر.

## الترقية من v1.1.0

المتطلبات المثبتة: Node 24.21.0 وnpm 10.8.2 وMariaDB 10.11.18. لم يتغير محرك قاعدة البيانات أو إطار الواجهة، ولا تضيف حزمة تحضير الإصدار اعتماد تشغيل جديدًا.

تتضمن الترقية migrations إضافية:

| Migration | الغرض |
|---|---|
| `1791676800000-admin-revisions` | مراجعات القوائم والإعدادات للحماية من الكتابات القديمة |
| `1791676801000-worker-heartbeat` | قياس حياة العامل المستقل |
| `1791763200000-diagnostics` | تخزين التشخيص المنقح |
| `1791849600000-audit` | عقود أدلة التدقيق والتقارير والمراجعات والقواعد والصحة |

1. راجع [دليل التدقيق التشغيلي](../migration/audit-70/runbook.md)، واحفظ نسخة احتياطية موثقة مع إيقاف الكتابات أثناء الانتقال.
2. طبّق migrations بحساب مخصص، ثم راجع حساب التشغيل الذي يملك SELECT/INSERT فقط على AuditLog. إزالة FK التاريخي تمنع حذف الحساب من إعادة كتابة الدليل.
3. شغّل API والعامل المتوافقين مع المخطط نفسه و`DATA_DIR` خاص مشترك والأسرار الصحيحة؛ لا تُشغّل كاتبًا قديمًا يعدّل AuditLog مع الحماية الجديدة.
4. راجع أذون `audit.*` و`diagnostics.*`. لا تُمنح أذون التدقيق الجديدة تلقائيًا للأدوار الأخرى، ويبقى `super_admin` شاملًا وفق نموذج المشروع.
5. تحقق من تغييرات الطلبات وحدثها، والفحص التقني للعامل وAPI، وتقرير اصطناعي كامل وتنزيله، ورفض مستخدم غير مخول قبل استئناف التشغيل المعتاد.

القواعد معطلة والاحتفاظ بالأحداث غير مهيأ افتراضيًا. ملفات التقارير مؤقتة لمدة 24 ساعة؛ انتهاء الملف لا يحذف الأدلة. حفظ ملف تقرير وchecksum يتحقق من تغير بايتاته ولا يثبت صحة أصله ضد مسؤول قاعدة البيانات.

## التحقق وحدود الادعاء

[أدلة إصلاح الصحة](../migration/audit-72/README.md) تثبت 895 اختبارًا و240 مسار متصفح على `d978938`، ومنها AR/EN و375/1280 ولوحة المفاتيح وaxe. حزمة التحضير تحدّث التوثيق ورقم النسخة، وتصلح تسمية حقل المرفق وإخفاءه الدلالي بعد كشفه في فحص axe؛ فحوص PR والدمج على GitHub هي مرجع كل SHA مرفوع، وتُراجع قبل نشر الإصدار. [تقرير تحضير الإصدار](../migration/release-74.md) يربط النطاق والفحوص والصور.

فحص المرجع التاريخي في CI مستقل عن المنتج؛ استخدام Bun هناك لا يضيف اعتمادًا لتشغيله. لا توقيع خارجي للأدلة أو تخزين مستقل أو إرسال تنبيهات خارجي مفعّل بهذا الإصدار. الاستعادة خارج المضيف والنشر وترحيل بيانات الإنتاج إجراءات منفصلة؛ لا دعوى امتثال أو حصانة مطلقة من العبث.

## English summary

v1.2.0 brings the bilingual audit investigation workspace, historical evidence and transactional recording, worker-backed reports, independent reviews, deterministic alerts and health checks. It also includes correlated diagnostics, reliable request mutations, retained drafts and failure state, complete bounded CSV downloads, stale-write protection, worker monitoring and response-deadline improvements.

Upgrading from v1.1.0 requires the four explicit migrations above, a reviewed pause of writers, separate migration/runtime identities, append-only audit grants, and compatible API/worker processes. New audit permissions are independent; retention is unconfigured and rules are disabled by default. Read the [audit runbook](../migration/audit-70/runbook.md) before upgrading. This GitHub release does not deploy the application or migrate production data.
