## حدود مختلفة لا يجوز الخلط بينها

- **مغلف الشجرة الجديد:** 300,000 بايت UTF-8 قبل التطبيع وبعده. أثبتت MariaDB والـHTTP الحفظ والنشر والعرض بالحجم الكامل على `/api/admin/pages` و`/api/v1/admin/pages`، مع تعارض متزامن 200/409 وثبات البصمات بعد رفض مدخل أكبر أو توسع افتراضي.
- **جسم طلب HTTP الانتقالي:** 160MiB = **167,772,160 بايت** في Express وNginx. أُرسل هذا الحجم فعليًا على loopback وحصل على 200؛ حصل بايت إضافي على 413. الطلب غير الموثق الأكبر حصل على 401 قبل محلل الجسم. يحتوي اختبار الحد على JSON صغير ومسافات صحيحة نحويًا؛ النتيجة المخزنة بايتان، ولذلك ليس هذا إثبات تخزين 160MiB.
- **تخزين JSON القديم:** اختُبرت منفصلًا 60 كتلة columns، كل منها 4 أعمدة و10 فقرات بطول 4000 ووصف عربي، باستخدام محارف مسلسلة لتمرين كلفة escaping في SQL. المخزن **57,713,811 بايت لكل لغة**، أي **115,427,622 بايت للوثيقتين** في عملية حفظ واحدة؛ وتطابقت SHA-256 في المسودة والمنشور وPageVersion. ليست هذه برهنة رياضية للحد الأقصى لجميع تراكيب أنواع الكتل، ولا قياسًا للأداء البصري عند هذا الحجم.
- **MariaDB packet:** البيئة الفعلية للتجربة 268,435,456 بايت (256MiB). ليست إعدادات الجهاز دليلًا على إعدادات خادم آخر. النشر وحفظ لغتين يحتاجان مساحة لحزمة SQL أكبر من قيمة JSON منفردة، خاصة مع escaping.

`http-summary.json` يسجل المقاسات والنتائج والبصمات دون النصوص الكبيرة. يولد `tools/migration/cms-boundary-fixture.mjs` نصًا عربيًا ذا محتوى فعلي عند الحد؛ لا ملفات بيانات كبيرة أو خاصة في Git.

## تشغيل الحدود وإعداد البيئة

بعد البناء وترحيلات قاعدة اختبار معزولة على loopback، شغّل `npm run test:cms-boundaries`. يشترط اسم `so7ob_*_test` ومنفذ/مضيف الاختبار ومفتاح حساب القاعدة عبر البيئة. ينشئ صفوفًا اصطناعية تخص تشغيله ثم يحذف صفوفه فقط؛ لا seed أو reset. لا تشغله بالتوازي مع اختبارات تستخدم قاعدة البيانات نفسها أو مع بناء Vite على مخرجات خادم المتصفح.

أضيف `npm run db:check-cms`: فحص مخطط و`@@session.max_allowed_packet` للقراءة فقط، يفشل إذا كان أقل من 256MiB. أصبح شرطًا في ExecStartPre لقالب خدمة API حتى لا يبدأ استقبال الكتابات الكبيرة بإعداد غير كافٍ. ملف `ops/mariadb/so7ob-cms.cnf` قالب إعداد للوجهة المعتمدة فقط؛ لا تثبيت أو إعادة تشغيل تلقائية. بعد تطبيق إعداد MariaDB يدويًا في نافذة معتمدة، يجب إعادة فتح اتصالات التطبيق ثم تشغيل الفحص؛ تغير global لا يغير جلسة مفتوحة قديمة.

في CI فقط، تُضبط خدمة MariaDB الاصطناعية أولًا على 16MiB لإثبات رفض الفحص، ثم على 256MiB وتُفتح اتصالات جديدة للتحقق الإيجابي وتشغيل النقل الكبير. لا تغير الأداة المحلية global ولا تتصل بقاعدة التطوير أو المصدر أو الإنتاج. إعداد Nginx يبقى 160m؛ التجربة الكبيرة تستخدم Nest مباشرة، وفحص Nginx المستقل يثبت صلاحية القالب ولا يُعد قياس نقل 160MiB عبر وكيل إنتاجي.

هذه أدلة قبول محددة، وليست اكتمالًا للمهمة: بقية رحلات الأدوار والكتل والقياسات ذات الجولات الخمس والقبول البصري العام وإزالة الاعتماد المرجعي الانتقالي ما زالت مستقلة. لا بيانات إنتاج ولا نشر أو تحويل.
