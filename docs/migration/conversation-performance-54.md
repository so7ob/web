# قياس قائمة الإدارة والمحرر — #54

يعتمد PR على #55، وبعده تبعًا #48 و#51؛ القاعدة develop. لا تدخل تغييرات المحرر في إصلاحات P1.

## الاستعلام

بيئة القياس: Node 24.21.0، MariaDB 10.11.18 على loopback، 20 طلبًا و20 استفسارًا،
1000 رسالة لكل سجل وجسم اصطناعي 1024 بايت. اتصال دافئ وخمس عينات لكل نوع.
الأداة `tools/migration/conversation-list-benchmark.mjs` ترفض قاعدة غير اختبارية أو بعيدة،
وتتطلب خلو جدولي الطلبات والاستفسارات، وتنظف سجلاتها وحدها. لا تقرأ ملفات .env تلقائيًا.

قبل: 20000 صف رسالة من كل قائمة إلى Node. وسيط زمن القائمة 148.03ms للطلبات و159.55ms
للاستفسارات. عدد الرسائل المعروض 1000 لكل سجل كما هو مطلوب.

بعد: الطلبات تعتمد بالفعل على lastClientReplyAt/lastStaffReplyAt، لذا أزيل الاستعلام الزائد؛
الاستفسارات تستخدم استعلام آخر رسالة عامة لكل سجل، بحد أقصى20 صفًا. التعادل الزمني يُحسم
بالمعرف تنازليًا بدل ترتيب غير محدد. الملاحظات الداخلية لا تمثل ردًا، لكنها تبقى في العدد.
الفهرس القائم `(inquiryId,createdAt)` كافٍ للقياس الحالي؛ لا migration أو فهرس إضافي دون حاجة مثبتة.
تظل قراءة COUNT مرتبطة بطول المحادثة داخل MariaDB؛ لم ندّعِ تكلفة ثابتة أو سعة إنتاجية.

## المحرر

تقسيم المسارات الكسول موجود. قيس حجم chunk وgzip وزمن DOMContentLoaded والوصول إلى زر
القوالب على جلسات عربية/إنجليزية 375/1280، دون إبطاء شبكة مصطنع. القياس المحلي الصغير ليس
تقييمًا لشبكات العملاء ولا يثبت موضع اختناق في المحرر؛ لذلك لم تُضف بنية أداء جديدة.
استُخرج حارس مغادرة المتصفح والتنقل الداخلي إلى `use-editor-navigation-guard.ts`، مع إبقاء
الحفظ والتعارضات والاختصارات والحوارات وعقود المستند كما هي. لا إعادة كتابة شاملة أو تخفيض
حدود المحتوى. هذا فصل صيانة وليس ادعاء تسريع للمحرر.

الأدلة الاصطناعية في `evidence/conversation-performance-54/`؛ التقرير النهائي يربط كل قياس
بمحتوى الكود وSHA، ونتائج البوابات المحلية وCI تسجل منفصلة في PR. اختبارات القائمة تشمل
تعادل التواريخ والملاحظات والعدد؛ رحلات المحرر القائمة تختبر الحفظ والنشر والتعارض واللغتين.
التراجع: revert للحزمة بعد المراجعة، بلا تغييرات مخطط أو بيانات. تبقى تبعيات P1 مستقلة.
