## التنفيذ

- PATCH إعدادات المسودة مع `draftSettings` يحفظ المحتوى والإعدادات دون تغيير الرابط أو SEO أو الظهور المنشور؛ baseRevision إلزامي ويُفحص داخل القفل والمعاملة. عناوين الإدارة مستقلة عن العنوان المنشور. النشر يحفظ لقطة الإعدادات ويزامن الأعمدة المستخدمة للصلاحيات وsitemap.
- POST publish بعقد المراجعة يدعم اختيار العربية/الإنجليزية، يتحقق من اللغة المطلوبة، يرفض المراجعة القديمة أو الأرشفة، ويحفظ إصدارًا عند تغير المحتوى فقط. تغيير الرابط ينشئ تحويلًا، وSSR يقرأ القيم الحالية دون إعادة بناء.
- POST discard يعيد المحتوى والإعدادات المنشورة إلى المسودة. POST versions/:version/restore يعيد اللغات المختارة فقط، ويرفض إصدارًا مفقودًا، ويحفظ المسودة السابقة تلقائيًا قبل الاستعادة، دون نشرها.
- POST schedule يتطلب pages.publish ومراجعة مطابقة وموعدًا بعد 30 ثانية على الأقل وبحد سنتين. publishAt=null يلغي الجدولة دون طلب مراجعة. المساران القديم و/api/v1 يستخدمان نفس الخدمة وDTOs.
- العامل المستقل يفحص الجدولة المستحقة دوريًا؛ القفل في MariaDB مشترك مع تحرير الصفحات. النشر والإصدارات والتدقيق والإشعارات وإزالة الجدولة ضمن معاملة واحدة. العطل غير المتوقع يُرجعها كلها وتبقى الجدولة مستحقة عند إعادة تشغيل العامل. أخطاء التحقق المتوقعة تُسجَّل كإسقاط موثق.

## استثناءات السلامة عن المصدر

1. المصدر يعيد draftRevision إلى publishedRevision عند discard. هذا يعيد استعمال رقم قديم: حفظ/جدولة بقرار قديم قد يطابقه لاحقًا (ABA). البديل يزيد المراجعة ويجعل publishedRevision مساويًا لها بعد إرجاع المسودة إلى المنشور؛ الاختبار يرفض الحفظ القديم ويسقط الجدولة السابقة. لا تتغير لقطة المحتوى المنشور أو توقيت نشرها.
2. المصدر يفحص مراجعة النشر خارج معاملة التحديث، ويستخدم قفل جدولة في ذاكرة العملية فقط. هنا يجري الفحص والكتابة تحت قفل قاعدة مشترك، ويثبت اختبار خدمتين مستقلتين نشرًا واحدًا. لا يُدَّعى exactly-once للإرسال الخارجي أو SMTP.
3. يُعاد فحص نشاط وصلاحية صاحب الجدولة عند التنفيذ؛ إزالة الصلاحية لا تترك قرارًا مؤجلًا ينشر لاحقًا بصلاحية مفقودة. لا تُحفظ جلسة ولا تمدد صلاحيتها.
4. فشل قاعدة البيانات لا يمحو الجدولة كما يفعل مسار catch المرجعي؛ تبقى العملية قابلة لإعادة التنفيذ بعد rollback.

5. اختبار `page-settings-null.test.ts` أثبت أن null الصريح في لقطة SEO يعيد قيمة الحقل القديم بدل مسحها. صُححت قراءة null دون تغيير fallback للحقول الغائبة أو اللقطة القديمة `{}`؛ سجل الفشل محفوظ.

## التوافق والحدود

ما زال محول الحفظ القديم بالطابع الزمني ومسارا publish/restore بلا جسم يخدمان عميل المحرر السابق. الطلبات الصريحة بالمراجعة تستخدم العقد الجديد؛ هذه مرحلة انتقالية معلنة حتى توصيل المحرر الجديد. لا يُقدَّم ذلك على أنه قبول كامل لعقود المصدر الجديدة. لم يُنقل تغيير الرئيسية الجديد أو عرض شجرة المعاينة ضمن هذا الجزء.

دليل MariaDB يغطي العزل، اللغات، الروابط، المراجعة، الاستبعاد، النسخ والاستعادة، التزامن، الأرشفة، الحساب الموقوف، وفشل التدقيق والتعافي. رحلة HTTP تتحقق من حجب المسودة وظهور HTML وSEO والتحويل فور النشر والصلاحيات وCSRF والمسارين. سياسة الجدولة الخالصة من المصدر مع اختباراتها محفوظة في حزمة العقود. تفاصيل الأعداد والفحوص النهائية تسجل بعد التنفيذ في evidence/publication/checks.json.

يبقى توصيل واجهة المحرر والقوالب والجدولة، والتتبع، والقبول البصري والأداء والاستعادة الشاملة وإزالة الاعتماد الانتقالي. بيانات الإنتاج لم تقدم ولم تُرحّل.
