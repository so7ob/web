# Atomic draft page copies (#120)

## Reproduction and source

The current list action was reproduced on develop `2e2382f72d850e4fb4c3c00d7a049d4b7fd23f34`: it sent only titles and a new slug to the normal empty-page creation endpoint. A synthetic source with one Arabic and one English block produced a draft with zero blocks in both languages. Archiving the copy retained those empty arrays; the source row stayed byte-for-byte unchanged. The defect is creation of an empty destination, not loss of source content or removal by archive.

Develop `0c904bbc1d7d9ec30c88d43d2dd6048fb69afc33` (PR148 merged) was subsequently merged into the independent `fix/120-copy-page-content` branch. The relevant page service/list source is unchanged between these develop heads. #100 remains preserved and separate; #111, #119 and #147 are excluded from this change.

## Copy contract

- `POST /api/admin/pages/:id/duplicate` and its `/api/v1/` mapping create a fresh draft from the **latest saved draft** in both languages. The action is explicitly named “Duplicate draft” / “نسخ المسودة”; publication is never implicit.
- Source read (`pages.view`) and destination edit (`pages.edit`) are required before source lookup. Missing and archived sources are rejected for an authorized caller; archived list actions remain disabled. Existing CSRF and HTTP authorization stay in force.
- Nested v1 content and supported legacy v0 content are validated using existing document rules. Languages stay independent; an empty language stays empty. Invalid content fails instead of becoming an empty successful copy. Document-local block IDs remain stable for anchors; page IDs and version histories are independent.
- Copy draft display titles, administrative titles, supported SEO titles/descriptions (including null) and the existing OG-media reference. The destination gets a new slug/order and normal new-draft visibility defaults. Do not inherit home status, access roles, publication snapshots, published revision/author/time, scheduled publication, source/seed identity or historical versions/audits.
- Keep references to existing media; do not duplicate or delete binary assets. Check references under the same CMS operation lock used by media deletion and other page writers. Missing media fails atomically.
- Allocate the existing five `-copy` / `-copy-N` candidates on the server under the CMS transaction lock, reserving page slugs, draft slugs and redirects. Truncate the base safely within the existing 60-character slug limit. Concurrent copies get different IDs/slugs; exhausted candidates fail without a partial page.
- Write one fresh `page.created` audit for the destination. Only the non-sensitive `sourcePageId` is added to that event's context allowlist; it remains excluded from other actions, and raw draft content/credentials remain redacted. Failure of that audit rolls back the new page. No old audit event is copied.
- The list makes one request, disables copying while it is pending, and reports success only after the server succeeds. A failed request must not create an empty fallback page or display a success toast.
