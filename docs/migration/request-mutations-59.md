## السبب المثبت والإصلاح

خصائص OperationBody الاختيارية تصبح خصائص موجودة بقيمة undefined في بناء ES2022. كان `"assigneeId" in body` يختار الإسناد رغم أن العميل أرسل priority أو status فقط؛ يؤدي ذلك أيضًا إلى رفض موظف الدعم بصلاحية غير مناسبة. تختار الخدمة الآن الحقول المرسلة فعليًا، وتحتفظ بـ null الصريحة لإلغاء الإسناد. لا تنظيف قائم على truthiness: false و0 والسلسلة الفارغة تدخل التحقق وتُرفض إن لم تكن قيمة صالحة للعملية.

العقد للواجهتين legacy/v1: عملية واحدة فقط من assigneeId أو priority أو status أو action في كل PATCH. note ترافق status فقط. رفض الجمع بين العمليات برمز invalid وحالة 400 قبل أي كتابة، بدل اعتماد أسبقية غير معلنة. لا تضيف العملية صلاحيات أو انتقالات حالات جديدة. تستخدم الواجهة الحالية عملية واحدة بالفعل؛ العملاء الخارجيون الذين كانوا يعتمدون على تجاهل جزء من طلب متعدد العمليات يحتاجون فصل العمليات.

تُرجع دالة الحفظ نتيجة صريحة؛ لا تُمسح ملاحظة الحالة أو سبب الإغلاق عند فشل الكتابة. هناك رسالة عربية/إنجليزية للانتقال المرفوض. إذا تأكدت الكتابة وفشلت إعادة الجلب، تظهر رسالة باقية تؤكد الحفظ وتطلب تحديث البيانات، وتُمنع الكتابة التالية حتى نجاح القراءة. زر التحديث يعيد GET فقط ولا يعيد PATCH. لا تخزين محلي لملاحظات خاصة.

اختبار axe كشف علاقة تبويبات الرد بمحتوى غير موجود في صفحة التفاصيل. أضيفت TabsContent للرد والملاحظة الداخلية مع إبقاء مسودة الملحن عند تبديل التبويب، وربط أسماء حقول المسؤول والأولوية والحالة. لم تُخفَ عناصر ولم تُوسع استثناءات الإتاحة.

## حدود التحقق والتراجع

MariaDB 10.11.18 معزولة، Node 24.21.0 وnpm 10.8.2؛ بيانات اصطناعية فقط. فحوص الواجهة بالعربية/الإنجليزية وRTL/LTR وعرضي 375/1280. فحوص الرفض: جلسة غائبة، صلاحية، CSRF/Origin، مدخلات خاطئة، انتقال مكرر 409؛ حفظ حقلين مستقلين بطلبين متزامنين والتدقيق وتاريخ الحالة. ليس فحص axe ادعاء امتثال شاملًا.

نُقل التطوير إلى `/root/So7ob/web` بناءً على توضيح المستخدم؛ worktrees السابقة محفوظة دون حذف، والفرعان #59/#61 لم يعودا محجوزين فيها. شُهد تشغيل فاشل لقاعدة اختبار جديدة قبل تطبيق migrations، وتشغيل آخر أُبطل بسبب تبديل الفرع أثناء الاختبار؛ لا يُحسبان نجاحًا أو عيبًا في الإصلاح. أُعيد البناء والاختبار بعد تثبيت الفرع وتطبيق migrations على القاعدة الاصطناعية فقط.

لا migrations أو تغييرات بيانات أو جلسات أو bcrypt في هذا PR. لم يجر اختبار الكتابة على طلب المستخدم الحقيقي. يُرجع التراجع كود PR عبر PR مستقل دون استعادة قاعدة بيانات؛ قد يعيد العطل الأصلي. نجاح CI أو دمج develop مستقبلًا لا يثبت تشغيل الإصلاح على localhost أو نشره في الإنتاج. لا دمج أو نشر تلقائي.
