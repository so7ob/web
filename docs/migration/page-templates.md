## الوظائف المنقولة

| المسار (وله محول `/api/v1` مطابق) | الصلاحية | السلوك |
| --- | --- | --- |
| GET `/api/admin/templates` | pages.view | إنشاء القوالب الستة المدمجة عند الحاجة دون استبدال الموجود؛ قائمة الأسماء والأوصاف واللغات وعدد العقد ومعاينة الأنواع ومرات الاستخدام واسم المنشئ، بلا محتوى كامل |
| POST `/api/admin/templates` | pages.edit | إنشاء قالب مخصص بلغة واحدة أو لغتين، حفظ JSON المطبع، رفض المحتوى غير الصالح أو غياب الاسم/المحتوى، وإرجاع 201 |
| PATCH `/api/admin/templates/:id` | pages.edit | تعديل الاسم والوصف للمخصص فقط؛ الغائب يبقى، الوصف الفارغ يمسح، ولا تغيير يرجع 400 |
| DELETE `/api/admin/templates/:id` | pages.edit | حذف المخصص مع التدقيق؛ القالب المدمج للقراءة فقط |
| POST `/api/admin/templates/:id/apply` | pages.edit | تطبيق اللغة المطلوبة على المسودة فقط، baseRevision إلزامي، نسخة احتياطية عند اختلاف المسودة عن آخر نسخة، زيادة المراجعة والاستخدام والتدقيق |

يُرفض القالب الذي لا يملك اللغة المطلوبة بدل الاستعاضة بمحتوى لغة أخرى. صفحة مؤرشفة أو مراجعة قديمة → 409؛ صفحة/قالب غير موجود → 404. كل معرف SQL ومدخل نصي مربوط بمعاملات؛ لا تُعاد كيانات قاعدة البيانات أو محتويات القوالب في قوائم metadata.

نقلت `builtin.ts` بيانات Website ذاتها، لا بيانات Rakim. نُقلت دوال تطبيع المدخلات والقائمة واختبارات القوالب إلى حزمة الخادم، واستُبدلت Prisma بخدمة TypeORM/QueryRunner. خريطة النقل وبصماتها في `evidence/page-templates/file-map.json`.

## الذرية والتوافق

- تطبيق القالب والنسخة الاحتياطية وعداد الاستخدام وسجل التدقيق ضمن معاملة MariaDB واحدة، وبقفل `cms-pages` المشترك مع المحرر القديم. مسار المصدر يحدث المسودة قبل معاملة النسخة/الاستخدام؛ لم يُنقل هذا الفصل. اختبار عطل AuditLog فعلي يثبت رجوع كل التغييرات معًا.
- GET القائمة المتزامن يُسلسَل بقفل مخصص، ولا يعيد كتابة قالب موجود بالمفتاح نفسه. يبقى إنشاء القوالب المدمجة عند القراءة مطابقًا لسلوك المصدر، مع اشتراط pages.view.
- تحفظ تحديثات الكتل القديمة واستعادتها زيادة draftRevision أيضًا؛ لذلك لا يتجاوز تطبيق قالب قفل المراجعة بعد تعديل سابق من المحرر القديم.
- حفظ شجرة v1 عبر مسار الصفحات يتطلب baseRevision مطابقًا. بقي عقد حفظ v0 بالطابع الزمني قائمًا خلال الانتقال.
- النشر والاستعادة يقبلان JSON الشجرة الجديد مع بقاء JSON المصفوفة القديمة كما كان. إصدارات الصفحة تخزن المحتوى نفسه لا كائن نتيجة المدقق، وعدّ العقد يدعم الصيغتين. هذه إضافة توافق، وليست إكمالًا لفصل إعدادات المسودة والنشر أو النشر الجزئي والجدولة.
- body parser للقوالب يستوثق الجلسة والصلاحية وOrigin/CSRF **قبل** تخصيص الجسم الأكبر. الحد الخارجي 4MiB لاستيعاب نصّي JSON بحد 300,000 بايت لكل لغة مع escaping؛ يبقى حد JSON العادي 128KiB وحد المحرر القديم منفصلًا. لا يمثل ذلك إثباتًا لحد 160MiB أو packet الإنتاج.

## أدلة الاختبار وحدودها

- اختبارات المصدر تتحقق من القوالب الستة ولغتيها والتطبيع وتوفر اللغة ومعاينة الأنواع.
- MariaDB فعلية على loopback:3307: أذونات سلبية، إنشاء مدمج متزامن وعدم استبداله، تعديل/حذف المخصص، عدم تسريب المحتوى إلى audit/metadata، النسخ والنشر والاستعادة، صفحة مؤرشفة ومراجعات مفقودة/قديمة، فائز واحد لتطبيقين متزامنين، وتراجع كامل عند فشل التدقيق.
- رحلة HTTP تقارن المسارين القديم وv1، تمنع الزائر والعميل وCSRF/Origin الخاطئ، تطبق القالب ثم تنشره وتقرأ HTML وتستعيد نسخة، وتختبر جسمًا صالحًا يتجاوز 128KiB ورفض الحجم الأقصى قبل/بعد المصادقة.
- أول اختبار سلبي استبدل كلمة heading في **المعرف** بدل النوع بالخطأ؛ قُبل المستند لأنه صالح. صُححت fixture لتغيير حقل type تحديدًا، دون تغيير المدقق أو تخفيف الشرط. السجل المحلي محفوظ في `.migration/templates/focused.log`.

اختبار الجسم الأكبر من 4MiB كشف أن خطأ body-parser كان يصل إلى مرشح الأخطاء العام كـ500. محول القوالب الآن يصنف `entity.too.large` صراحة إلى 413 دون تسجيل الجسم أو استبدال فحص الحجم. احتُفظ بسجل الفشل قبل الإصلاح.
