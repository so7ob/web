## التنفيذ

- snapshot المخطط القديم `schema-v1.json` لم يتغير. ترحيلا إنشاء المخطط وUTC القديمان يقرآن v1 صراحة حتى لا تتغير مخرجاتهما عندما يتطور مخطط التطبيق.
- `schema-v2.json` و`models.ts` يضيفان PageTemplate وTrackLink، وسبعة حقول للمسودة والمنشور والمراجعة والجدولة في Page. عدد نماذج المصدر 25؛ لا تدل إضافة المخطط على اكتمال خدمات القوالب والجدولة والتتبع.
- ترحيل TypeORM `1791072000000-source-v2` إضافي وصريح وقابل للاستئناف بعد DDL جزئي. لا يسقط جداول أو أعمدة، ولا يعيد كتابة bcrypt أو الرموز أو أوقاتها. MariaDB DDL ليست معاملة ذرية؛ أوقف الكتابات قبل الترحيل.
- يعيد backfill إعدادات الصفحات القديمة من أعمدتها، مع بقاء إعدادات النشر مستقلة. يتبع شرط المصدر القديم للصفحات المنشورة التي لها publishedBlocksAr. لا يعدّل قيم الإعدادات غير الفارغة عند إعادة تشغيل الترحيل.
- الترميز `utf8mb4_nopad_bin`، وأوقات UTC بدقة milliseconds، والفهارس والعلاقات وNULL والمفاتيح الاختيارية محفوظة. المخطط لا ينقل Prisma إلى تشغيل التطبيق.

## أداة النقل

تتعرف `data:transfer` على جيل المصدر من أسماء الجداول والأعمدة ثم تتحقق من **كل** عمود. مصدر v1 يبقى مقبولًا: تُشتق فقط حقول Page الجديدة، وتبقى حقول المصدر القديمة كما هي. مصدر v2 يحتفظ بنصوص JSON وبصمات الروابط وحالات الإلغاء والانتهاء دون تمديد أو تجديد.

يفشل النقل قبل كتابة الوجهة عند مخطط مصدر ناقص أو أعمدة/جداول مجهولة أو رابط تتبع لا يملك بطاقة واحدة مطابقة لنطاقه. لا تقوم الأداة بإصلاح قاعدة Website ذات الترحيلات الناقصة تلقائيًا.

تقارير النقل تعرض `sourceSchemaVersion` و`mappingVersion: 2`. بصمة المهمة تتضمن جيل التحويل؛ **لا يُستأنف journal صادر من أداة v1 بأداة v2**. أكمل مهمة النقل بنفس إصدار الأدوات أو جهّز وجهة معزولة جديدة بعد مراجعة الخطة؛ لا تحذف journal أو بيانات الوجهة لتجاوز الرفض. تستمر أوضاع dry-run/apply/resume/verify والتحقق من IDs والقيم والبصمات والملفات والأيتام.

## اختبارات فعلية

- تكررت رحلة النقل كاملة لكل من v1 وv2 على MariaDB فعلية: dry-run، رفض الوجهة الخاطئة، أعطال وسط النقل ثم resume، عدم التكرار، تحقق الحقول والملفات، الروابط الملغاة والمنتهية والقوالب وUTF-8 وNULL.
- `tools/migration/upgrade-source-v2-smoke.ts` يرفض أي قاعدة غير اختبارية أو غير فارغة. يبني المخطط القديم، ويحمّل جميع نماذجه الـ23 ببيانات اصطناعية، ثم يطبق ترحيل v2 ويتحقق من بقاء كل معرّف وقيمة قديمة، ثم يعيد الترحيل ويثبت عدم تطبيق أي تغيير إضافي.
- تجربة الترقية الناجحة: `so7ob_v2_upgrade_dates_test` على loopback:3307. احتُفظ بمحاولة تجهيز سابقة في قاعدة منفصلة؛ فشلت بسبب تحويل تاريخ SQLite النصي في سكربت التجربة، وأُصلح السكربت باستخدام التطبيع نفسه الذي تستخدمه أداة النقل. لم تُمسح القاعدة السابقة.
- اختبار تجهيز إضافي كشف تكرار حساب bcrypt لكل جدول؛ صار الحساب مرة واحدة لكل fixture، مع الحفاظ على cost 12 والتحقق من كلمة المرور، ودون زيادة مهلة الاختبار.
