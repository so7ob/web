## ما نُفذ

أضيف `npm run test:restore`: تجربة قابلة للإعادة تنشئ قاعدتين جديدتين بأسماء عشوائية مقيدة `so7ob_restore_*_test` على loopback، وترفض التشغيل دون `RESTORE_REHEARSAL=synthetic-only` أو في NODE_ENV=production. لا تقرأ قاعدة تطوير موجودة ولا تمس خدمة 3306 المحلية. لا DROP أو reset، وتُحفظ القواعد والمجلدات للفحص. حساب الاختبار يحتاج CREATE وصلاحيات على أسماء قواعد التجربة فقط.

تأخذ التجربة حزمة من ملفات API/worker/web/contracts/server المبنية، وpackage-lock، وتبعيات node_modules الفعلية، وpublic وops؛ تستخرجها إلى مسار مستقل وتقارن كل بايت بأرشيفها. تُثبت أن روابط حزم server/contracts تنتهي داخل النسخة المستعادة. يبدأ Nest والعامل من هذه النسخة، ولا يعتمدان على مسار dist الأصلي. لا تُنقل .git أو .env. يتضمن سجل الأدلة SHA للأرشيف وlock، وcommit الأساسي وحالة العمل المحلي؛ البصمة هي مرجع محتوى البناء الفعلي ولا تُنسب الملفات غير الملتزمة إلى commit الأساسي.

تُنشأ مفاتيح اصطناعية عشوائية في vault مستقل بصلاحية 0600 داخل مجلد 0700، ولا تدخل نسخة البيانات أو Git أو المخرجات. لا يمثل ذلك تكاملًا مع مخزن أسرار إنتاجي؛ حفظ المفتاح الحقيقي واستعادته من مخزنه يحتاجان تجربة منفصلة في البيئة المعتمدة.

## النتائج المثبتة

- قُتل عامل حقيقي بـSIGKILL بعد وصول DATA إلى خادم SMTP اصطناعي دون وصول تأكيد القبول إلى العامل. بقيت الرسالة `sending` في النسخة الاحتياطية؛ عند الاستعادة أصبحت `uncertain` ولم تُرسل مجددًا.
- نُقلت جميع جداول MariaDB الموجودة وقورنت مجموعات الصفوف والقيم والتواريخ والمعرّفات كاملةً قبل فتح التطبيق. يحفظ `summary.json` العدد والبصمة لكل جدول دون الصفوف. بعض الجداول خالية في هذه العينة؛ ليست هذه تجربة شاملة لكل حالات بيانات الترحيل.
- استعيدت ملفات الصور وUTF-8 وملف يتبعه تنظيف مؤجل؛ استجاب Nest المستعاد لطلب الصورة بالبايتات نفسها. استؤنف التنظيف دون حذف الملف المرجعي.
- بقيت الجلسة النشطة صالحة وانتهت الطلبات بالجسم المتوقع؛ بقيت الجلسات الملغاة والمنتهية مرفوضة، دون تمديد expiry أو إلغاء revokedAt. هذا تعافٍ داخل النظام الجديد؛ قرار إعادة الدخول مرة واحدة عند تحويل Website مستقل لم يتغير.
- أرسل العامل المستعاد الرسالة التي كانت queued فقط؛ تشغيله التالي لم يكرر إرسالًا. قياس SMTP لا يثبت وصول الرسالة إلى المستلم ولا exactly-once.
- رُفضت الاستعادة فوق قاعدة مأهولة قبل أي استبدال، وكذلك بعد إدخال كتابة جديدة عقب فتح النظام. بقيت الكتابة الجديدة موجودة وبقي المصدر الاصطناعي المجمد دون تغيير.
- نجحت خمس حالات CLI: المفتاح الصحيح، الخاطئ، المفقود، عدم إيقاف الكتابات، وعدم تطابق اسم القاعدة. نجح التحقق المتزامن للقراءة فقط، ورُفضت حمولة webhook تالفة حتى في صف تاريخي sent بعد أول دفعة من 100 سجل. تشمل العينة النهائية 102 webhook وتختبر رفض سجل تالف بمعرّف فارغ دون تخطيه في الاستعلام الأول.

المحاولات الأولى كشفت أخطاء في fixture نفسه: حقل MediaItem.url غير موجود، ثم مسار/نوع/معرّف ملف غير مطابق لعقد التنزيل، ثم اسم Setting بدل SiteSetting. صُححت بيانات التجربة بما يطابق المخطط ومسار `/api/media/:id` وقيود المصدر؛ لم تُعدّل صلاحيات المنتج أو شروط قبوله لتجاوزها. بقيت السجلات في `.migration/operational-restore/{first,second,third}.log`؛ النجاح الأول في `final.log`، ثم توسيع فحص الدفعات في `final-paginated.log`، والنهائي مع تسليم العامل للمفاتيح المقروءة من vault في `final-key-handoff.log`؛ بقيت نتيجة التجربة الأولى في `initial-summary.json`.

## فحص المفتاح قبل تشغيل العامل

أضيف `npm run data:recovery-check -- --confirm-database NAME`. يحتاج بيئة الوجهة المعتمدة وOUTBOX_KEY المستعاد و`MIGRATION_WRITES_PAUSED=yes`. يفحص تطابق اسم القاعدة وترحيلاتها ثم يفك توثيق جميع حمولات MailJob وWebhookJob، على دفعات 100، دون تعديل أي صف أو إرسال أي اتصال SMTP/webhook. مخرجات النجاح أعداد فقط؛ الخطأ منقح ولا يكشف المفاتيح أو النصوص. لا يشغّل هذا الأمر النسخ أو الاستعادة تلقائيًا.

يجب تشغيله **قبل** تشغيل العامل؛ العامل القائم يعامل الحمولة التي لا تُفك بالمفتاح المقدم بوصفها فاشلة، لذلك لا تستخدم تشغيل العامل وسيلة لاختبار المفتاح. فحص المفتاح لا يثبت توقف الخدمات تلقائيًا، ولا يثبت صحة ملفات التطبيق أو مطابقة البيانات أو جاهزية فتح الكتابات؛ هذه خطوات مستقلة في التجربة.

## إعادة التنفيذ وحدودها

ابنِ التطبيق أولًا ثم شغّل `npm run test:restore` مع `DATABASE_HOST=127.0.0.1`، ومنفذ MariaDB الاختباري وحساب تجارب مقيد، و`NODE_ENV=test` و`RESTORE_REHEARSAL=synthetic-only`. يلزم mariadb/mariadb-dump وtar ومساحة للحزمة والنسخة المستخرجة. لا تطبع كلمة المرور أو المفتاح ولا تضعهما في أوامر متتبعة. CI يشغّل التجربة على MariaDB service اصطناعية، وحساب root الخاص بتلك الخدمة فقط.

هذه تجربة استعادة محلية على المضيف نفسه ونسخة Node الحالية؛ لا تختبر فقد المضيف أو استعادة نظام التشغيل أو DNS/TLS الإنتاجي أو جلب أسرار فعلية. لم تُقدّم بيانات الإنتاج ولم تُرحّل. لا تغلق #6 أو #7 أو #1 بهذه النتيجة؛ تبقى تغطية بقية أعمال العامل، والقبول الشامل وقياسات الأداء والتجربة البيئية النهائية مستقلة. تظل نافذة الرجوع الكامل قبل فتح الكتابات؛ بعد فتحها يُحفظ MariaDB والملفات والطابور والكتابات اللاحقة ويُتعافى للأمام.
