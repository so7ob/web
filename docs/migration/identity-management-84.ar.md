# دليل إدارة المستخدمين والأدوار والصلاحيات

يرتبط هذا الدليل بـ [التنفيذ ومصفوفة التفويض وأدلة التحقق](identity-management-84.md)، و[Issue 84](https://github.com/so7ob/web/issues/84). يحتفظ النظام بدور واحد لكل مستخدم.

## الوصول والتنقل

من صفحة `/ar/admin/users` أو `/en/admin/users` تظهر روابط المستخدمين والأدوار ودليل الصلاحيات والدعوات وفق صلاحيات الجلسة. يشترط دخول الإدارة امتلاك `admin.dashboard`؛ اسم الدور المخصص وحده لا يمنح أي وصول. يفحص الخادم الصلاحيات في كل طلب، بما فيها طلبات الجلسات المفتوحة قبل التعديل.

## إنشاء دور وإسناده

1. افتح «الأدوار»، ثم أنشئ دوراً أو انسخ دوراً مسموحاً. أدخل مفتاحاً ثابتاً وفريداً واسماً ووصفاً بالعربية والإنجليزية.
2. اختر الصلاحيات من مجموعاتها. يمكن البحث وإظهار المختار فقط وتحديد المجموعة؛ تظهر المتطلبات والصلاحيات الحساسة في المحرر.
3. افتح المعاينة وراجع الإضافات والإزالات وعدد المستخدمين المتأثرين قبل التأكيد.
4. إسناد الدور يتطلب صلاحية الإسناد وحدود تفويض صريحة: امتلاك القدرة لا يكفي لمنحها. يضبط المدير الأعلى حدود التفويض، وتظل مجموعة فرعية من صلاحيات الدور.
5. عند تعارض نسختين، أعد فتح الدور وراجع أحدث قيمه قبل إعادة المحاولة. لا يستبدل الحفظ تعديل مدير آخر بصمت.

لا يمكن تعديل دور المدير الحالي لتوسيع سلطته، أو نسخ امتياز `super_admin`، أو أرشفة دور نظامي. ترفض الأرشفة وجود مستخدمين أو دعوات معلقة أو صفحات منشورة/مسودات تشير إلى الدور. تنقل هذه المراجع صراحة إلى دور صالح أولاً.

## إنشاء حساب مباشر

«إضافة مستخدم» تنشئ حساباً فور نجاح الحفظ. «دعوة مستخدم» إجراء منفصل، ويحتفظ بعقد API السابق.

- **كلمة مرور مؤقتة:** تعمل دون SMTP. تظهر مرة واحدة بعد النجاح وتتيح النسخ؛ تنتهي بعد 24 ساعة ويلزم تغييرها قبل استخدام أي وظيفة محمية. لا يسجلها التدقيق ولا ترسل بالبريد. احتفظ بها فقط بالقدر اللازم لتسليمها بأمان؛ عند فقدها، استخدم إعادة الإصدار ولا تكرر إنشاء الحساب.
- **رابط إعداد كلمة المرور:** ينشأ الحساب بحالة انتظار إعداد الاعتماد. صلاحية الرابط 30 دقيقة، ويستهلك مرة واحدة. «أُدرجت الرسالة للإرسال» تعني الإدراج المشفر في الطابور، ولا تثبت وصول البريد. إذا تعذر الإدراج، يبقى الحساب موجوداً وتظهر الحاجة لإعادة الإرسال من صفحة المستخدم.

البريد يطبع قبل الحفظ وتمنع قاعدة البيانات التكرار حتى في الطلبات المتزامنة. يجب إلغاء الدعوة المعلقة للبريد نفسه صراحة قبل إنشاء الحساب المباشر. لا يؤدي الإنشاء الإداري أو إعداد كلمة المرور إلى توثيق البريد.

## إدارة الحساب والأمان

صفحة المستخدم تعرض بياناته ودوره وصلاحياته ومصدرها، وحالة الحساب والتحقق من البريد وإعداد الاعتماد بصورة مستقلة. تغيير الاسم، وإسناد الدور، والتعليق، وإدارة الجلسات والاعتماد صلاحيات منفصلة.

التعليق يتطلب سبباً ويبطل الجلسات. إعادة التفعيل لا تعيد الجلسات السابقة. يمكن عرض بيانات الجلسات الآمنة وإنهاء جلسة محددة أو جميع الجلسات، بحسب الصلاحية. إعادة إصدار اعتماد مؤقت تتطلب كلمة مرور المدير الحالية وصلاحية مستقلة؛ العمليات على الحسابات المحمية تتطلب أيضاً التفويض الخاص. لا تتيح هذه الواجهة تغيير بريد الحساب.

لا يمكن جعل آخر مدير أعلى صالح غير قابل للاستخدام. يحمي الخادم هذه القاعدة داخل المعاملة حتى عند تزامن الطلبات. لا يحذف التعليق طلبات المستخدم أو رسائله أو سجله التاريخي.

سياسة كلمات المرور الجديدة تطبق حد bcrypt البالغ 72 بايت UTF-8، ويحسب النص العربي بالبايت؛ تظل تجزئات كلمات المرور القديمة متوافقة عند تسجيل الدخول.

## الدعوات والتدقيق والفشل

تعرض الدعوات الدور والمرسل والتواريخ والحالة: معلقة، مقبولة، منتهية أو ملغاة. إعادة الإرسال تبدل الرابط السابق. يعيد قبول الدعوة التحقق من صلاحية المرسل وحدود تفويضه والدور الحالي؛ الدعوة القديمة لا تتجاوز سحب التفويض.

تظهر تغييرات المستخدم ضمن نشاطه وفق `audit.view`، وتظهر أحداث الدور ضمن تفاصيله. يسجل النظام الفروق الآمنة والمنفذ والهدف والنتيجة والسبب ومعرف الترابط؛ لا يسجل كلمات المرور أو الرموز أو الكوكيز.

عند الفشل يبقى النموذج ومدخلاته مفتوحين. اقرأ خطأ الحقل أو الرسالة المحددة، وانسخ مرجع الخطأ إن ظهر. إذا انقطع الرد أثناء عملية حساسة، أعد تحميل الحساب/القائمة لتحديد النتيجة قبل إعادة الطلب؛ لا يمكن استرجاع كلمة المرور المؤقتة من استجابة سابقة.

## النشر والاستعادة

الترحيل إضافي وصريح. اختبره على نسخة اصطناعية أولاً، وأوقف الكتابة وخذ نسخة احتياطية وفق إجراءات المشروع قبل أي تنفيذ إنتاجي مصرح. يوقف تعارض البريد المطبع الترحيل حتى تتم تسويته؛ لا تستخدم حذف البيانات أو إعادة البذر لمعالجته.

عند نشر جزئي أبقِ الكتابة متوقفة، وأكمل الترحيل/الكود المتوافق وافحص الجاهزية. بعد استئناف الكتابة يكون الإصلاح إلى الأمام؛ إسقاط أعمدة الاعتماد أو استعادة نسخة قديمة قد يفقد تغييرات أمنية وبيانات حديثة. لم تنفذ هذه المهمة نشراً أو ترحيلاً لبيانات الإنتاج.
