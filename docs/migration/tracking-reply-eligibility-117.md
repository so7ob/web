## Change and boundaries

Tracking view now scopes its reply flags to the current session using the same ordered eligibility predicate as reply. Active/pending-verification owners without staff-reply permission remain eligible, including an owner with a non-client role lacking that permission. Accounts with the scope's staff-reply permission remain barred from posting as the client. Logged-in nonowners cannot borrow anonymous link-reply eligibility. Guest modes, force-login precedence, revoked/expired generations, workflow access, closed/archive rules, transactions, duplicate protection, author identity and HTTP codes are retained.

The global policy resolver and administrative policy display retain their existing meaning. Successful tracking views and reply403s can additionally supply a small allowlisted denial reason. These values contain no role, contact, capability or internal note. A staff-workspace hint additionally requires the existing administrative dashboard/view permissions, ready credentials and `assertWorkflowAccess` without the owner bypass; owner tracking access cannot grant an administrative route.

The client maps explicit safe reasons to Arabic/English guidance. Unknown403s become a generic session-unavailable message. A rejected draft stays in a labelled, enabled, read-only textarea on the same page so it can receive keyboard focus and be selected/copied. There is no automatic retry, storage persistence or capability-bearing login URL. A new card clears the draft/refusal state; a stale response cannot append a message or clear a different card's draft. The staff link is constructed as a localized internal route only when the server grants the safe hint.
