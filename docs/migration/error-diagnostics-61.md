# عقد الأخطاء والتشخيص — #61

Issue: https://github.com/so7ob/web/issues/61. بداية الاستكمال من develop `0e43775eed68a1165d05d05766c44465d09baa56`؛ العمل من `/root/So7ob/web` فقط. دمج المتطلبين #60 و#63 محفوظ دون إعادة كتابة التاريخ. هذا التقرير يسجل التنفيذ تدريجيًا؛ اكتمال #61 يحتاج واجهة الأخطاء وشاشة الإدارة والفحوص الختامية، وليس الخادم وحده.

## عقد الخادم

يحافظ legacy/v1 على HTTP status وcode والحقول المعروفة. يضيف الرد الفاشل category/messageKey/requestId/errorId ورؤوس X-Request-Id/X-Error-Id، مع Retry-After الأصلي. يولد الخادم UUID مبكرًا قبل parser والحراس ولا يثق بمعرّفات واردة من العميل. العطل غير المتوقع internal_error، وليس افتراض storage. استجابة 500 لا تحمل extra أو SQL أو رسالة استثناء خام. أخطاء ValidationPipe تحافظ على رموز الحقول الآمنة القائمة مثل password_short، وتستخدم invalid بدل نصوص المكتبة الخام. سجل JSON وصلاحياته مستقلان عن AuditLog ومعاملات الأعمال.

يُلتقط SHA البناء في build-info.json ثم مرة واحدة عند تحميل العملية؛ لا يتبدل SHA عملية قديمة عند بناء إصدار جديد على القرص. الأرشيف بلا Git يصرّح unavailable، والبناء مع تغييرات ملتزم بها جزئيًا يصرّح dirty. لا يمكن استنتاج إصدار العملية الفعلية من فرع checkout وحده.

## الخصوصية والتخزين

- allowlist للحدث/الرمز/نوع المكوّن/HTTP/أسماء الحقول، دون قيم المدخلات أو Cookies/Authorization أو SQL/parameters أو نصوص المحادثات. الاستثناء يحتفظ بنوع معروف وسبب تقني مصنف ومواقع أسطر من apps/packages؛ لا رسالة خام أو مسارات شخصية. المسار قالب بلا query أو معرف مورد/رمز وصول. لا جمع تلقائي لـDOM أو الصور أو نماذج المتصفح.
- DiagnosticEvent: سجل منقح في MariaDB عبر autocommit منفصل، يمكن تتبعه بعد rollback. DiagnosticReview لتصنيف المتابعة فقط؛ resolved لا يثبت إصلاح الكود. AuditLog يوثق تغيير التصنيف ولا يُحذف بسياسة التشخيص.
- احتفاظ التشخيص: 30 يومًا/50000 صف، تنظيف مرة في الدقيقة عند ورود أحداث (حد تشغيلي تقاربي أثناء الدفق، لا حذف دوري خارج التشغيل). التجميع حسب بصمة آمنة؛ الأعداد للأحداث المحفوظة المطابقة للمرشحات فقط، وليست إحصاءً شاملًا عند فقد التخزين أو انتهاء الاحتفاظ.
- ملفات داخل DATA_DIR/diagnostics: 0700 للمجلد و0600 للملف، 5MiB لكل ملف و4 نسخ، تنظيف الملفات القديمة بعد 7 أيام وحد إجمالي 50MiB عند الكتابة. لا تُخلط بملفات الأعمال أو AuditLog.
- مخرج stderr JSON مستقل عن DB والملفات، وطابور الحفظ محدود 256، وطابور الملف 128 وحد تراكم stderr قدره 1MiB. تُعرض أعداد فشل الحفظ/المخرج لهذه العملية منذ بدئها؛ لا ادعاء أنها تعد أخطاء جميع العمليات. يجب على المشغل ضبط تدوير journald/مجمّع stderr أيضًا؛ لا يعدّل التطبيق إعدادات المضيف. فشل التسجيل لا يخفي الخطأ الأصلي.

## إدارة السجل

`GET /api[/v1]/admin/diagnostics` و`/export` بصلاحية diagnostics.view؛ `PATCH /:fingerprint` يحتاج diagnostics.manage وdiagnostics.view مع CSRF/Origin. لا منح تلقائي لمدير العمليات/الدعم/العميل؛ مدير النظام يحتفظ بصلاحياته الكاملة القائمة. مرشحات ID والوقت UTC والخطورة والمكوّن والعملية والرمز؛ 20 مجموعة في الصفحة وحد أقصى 2500 صفحة. كل مجموعة تعرض آخر حدث مطابق بعد إعادة إسقاط الحقول المسموح بها. التصدير JSON منقح **للصفحة الحالية فقط**. لا روابط موارد أعمال لأن السجل لا يحتفظ بمعرفاتها؛ لا يمنح عرض التشخيص حق قراءة المحادثات أو المستخدمين.

## التحقق والحدود

اختبارات مركزة: 7 اختبارات وحدة/MariaDB/HTTP تشمل 400/401/403/409/429/500 وparser 400/413 وRetry-After، فشل المخزن والمخرج، تنقيح أسرار اصطناعية متداخلة، rollback، تجميع وتزامن وتصنيف وتدقيق واحتفاظ. اختبارات البناء الحقيقي في diagnostics-http.spec.ts تقارن ID الرد بسجل MariaDB، وتختبر منع العميل من القراءة والتصدير والتصنيف في legacy/v1. اختبارات العقود القديمة تحافظ على المساواة الدقيقة مع إضافة حقول التتبع الجديدة. دليل الجولة الأولى كشف توقعًا قديمًا للرد بلا الإضافات، ثم صُحح الاختبار للتحقق منها؛ لم تُخفف صلاحيات المنتج.

ستُربط البوابات الكاملة وSHA المرفوع بنتائج CI الفعلية في PR. لا يُنسب نجاح نسخة إلى نسخة لاحقة. كل البيانات اصطناعية؛ لا كتابة على طلب المستخدم، ولا تطبيق migration على قاعدة تشغيله، ولا نشر. migrations إضافية صريحة؛ التراجع عبر PR للكود مع إبقاء الجداول الإضافية؛ down المدمر مرفوض. إيقاف العامل أو DB لا يمنح الإذن بإعادة إرسال uncertain.

كشف CI الأول 38101297885 تراجعًا في رموز المصادقة عند تعميم invalid. أُعيدت الرموز الآمنة الأصلية بقائمة سماح، وبقي اختبار auth-smoke الصارم دون تخفيف؛ النجاح النهائي مرتبط برأس الإصلاح اللاحق.

## نتائج الفحص الكامل والتوافق

كشف CI 38102516492 أن مقارنة legacy/v1 كانت تقارن UUID مختلفين لطلبين مستقلين؛ عُدّل الاختبار ليؤكد العقد كاملًا لكل 403 وتطابق معرّفاته مع رؤوسه واختلافهما بين الطلبين، مع إبقاء المساواة الدقيقة لردود النجاح. أُعيدت رموز CMS الثابتة، ومنها content_too_large، دون تخفيف حدود المحتوى.

انتقال موثق لرموز CMS الديناميكية فقط: الرموز التي كانت تضم قيمًا بعد النقطتين مثل block_schema:... وanchor_duplicate:... تُعرض الآن برمز الأساس الثابت block_schema/anchor_duplicate، دون إعادة قيمة المستخدم في رمز الخطأ. category/messageKey يقدمان الترجمة. الرموز الثابتة والصلاحيات والحالات وواجهات legacy/v1 باقية. فحص HTTP يؤكد حجب لاحقة اصطناعية سرية.

عزل الاختبارات: fixture الحصة يعطي اختبار القبول الجديد حصة loopback مستقلة ثم يعيد الأصل بدقة؛ لا تغيير في limiter المنتج ولا تجاوز لـ429 داخل الاختبار. كان اختبار تعارض القوائم يعيدها عبر API يستبدل المعرفات، فتكرر global setup لاحقًا عناصر seed حتى بلغت 18 وتجاوزت حد 12 الصحيح. أصبح الاختبار يعيد صفوفه الأصلية ومعرفاتها بالضبط؛ القاعدة المحلية الملوثة محفوظة، والجولة النهائية في قاعدة اصطناعية جديدة. لم يُرفع حد القوائم ولم تُحذف بيانات المستخدم. محدد رد الدعم يبحث داخل المحادثة لتجنب مطابقة مسودة الكتابة أيضًا.
