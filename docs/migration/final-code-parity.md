# قبول نقل الكود والوظائف — #7

## النطاق الحالي

حصر المستخدم المهمة في نقل كود ووظائف Website إلى web، واستبعد التشغيل الفعلي صراحةً. لا يشمل هذا القبول تهيئة خادم أو نشرًا أو نطاقًا أو ترحيل بيانات إنتاج. قبول الشكل والأداء من المستخدم في 2026-10-06 باقٍ؛ ليس نتيجة قياس آلي جديدة. الوثائق السابقة تسجل حدود مرحلتها ولا تمثل وحدها الحالة الحالية.

المصدر المثبت `dddf8cd00a19cf7d562f503549f4c000109057d1`: تحقق بعيد مباشر، ولم يوجد develop في المصدر. طوبقت 1584 بصمة Git blob من شجرة GitHub مع اللقطة المعزولة دون اختلاف. source-check.json يسجل وقت الفحص. المصدر بقي للقراءة فقط. الجرد الحالي 25 نموذج مصدر و34 صفحة و60 ملف API و82 معالجًا صريحًا، بالإضافة إلى GET/POST الخاصين بـNextAuth؛ 27 كتلة و4 حاويات. جداول الجلسات والطابور والأقفال الإضافية في الهدف ليست نماذج مصدر مفقودة.

## أدلة المحرر

- 31 سجل خصائص وقيمه الافتراضية مطابق لتعريفات المصدر كما سجل التدقيق السابق. أضيفت 368 حالة عربية/إنجليزية لكل حقول السجلات والحقول المتداخلة: النصوص، الأرقام والتحويل الصحيح وحذف القيمة الفارغة، مفاتيح التشغيل، اختيارات string/number والاختيار الاختياري، إضافة/حذف/ترتيب القوائم، المجموعات وصفوف الجداول، مع حفظ قيم الأشقاء.
- 1550 حالة schema مشتقة من تشغيل مخططات المصدر نفسه، وليست توقعات مولدة من الهدف. تقارن القبول والرفض وبصمة الناتج المطبّع عبر الأنواع الـ27. أداة إعادة التوليد تتحقق من بصمات ملفات المصدر أولًا. الاختبارات السابقة تغطي التخزين ثنائي اللغة في MariaDB، النشر والإصدارات والاستعادة، والتزامن والتعارض والتراجع والسحب والنسخ والمعاينة والقوالب والجدولة.
- الرحلات الحقيقية تستخدم لوحة المفاتيح، الحفظ وإعادة التحميل والقراءة من MariaDB؛ لا يعتبر رندر الحقل وحده دليل حفظ. الاستثناءات الأمنية/الإتاحية المثبتة سابقًا باقية، ومنها معرّفات الحقول وطبقة السحب والعنوان الدلالي وظهور Hero والتطبيع الآمن.

## عقود API والمصادقة

اختبارات role-contracts تمر على قراءات الإدارة لكل دور: العميل والدعم ومدير العمليات والمحرر ومدير النظام، وتطابق حالة HTTP والجسم بين legacy وv1، إضافة إلى رفض الزائر على جميع handlers المحمية في الجرد. اختبارات الخدمات الحالية تكمل عمليات الكتابة والملكية والرفض والتزامن والتراجع. جرد OpenAPI ليس بديلًا عن هذه الاختبارات.

وجد التدقيق نقصًا حقيقيًا: providers أعلن signinUrl غير منفذ، وصفحات NextAuth العامة لم تكن مكتملة، وإرسال form عادي كان يتلقى JSON بدل التحويل. أضيفت signin/signin/credentials وتأكيد GET signout الذي لا يبطل جلسة قبل POST، وverify-request وerror مع أكواد 200/403/500 الموروثة. النموذج العادي يتحول بـ302؛ طلبات JSON وjson=true تحتفظ بعقدها. يفحص الاختبار عدم الخروج بمجرد GET، وCSRF المزور، ومنع التحويل الخارجي، وRTL/LTR وaxe وعرضي 375/1280. نُقلت شاشة الدخول إلى واجهة الموقع الحالية بدل إعادة تشغيل صفحات NextAuth؛ الشاشة الوسيطة ثنائية اللغة لا تدّعي إرسال بريد لمجرد زيارتها. OAuth والبريد كـprovider ليسا مفعّلين في المصدر ولا يضافان هنا. قرار إعادة الدخول مرة واحدة وعدم نقل JWT القديم باقٍ.

رحلات الإدارة الجديدة تحفظ القوائم والإعلانات من الواجهة، تتحقق من إعادة التحميل وMariaDB وظهورها فورًا في HTML العام والتدقيق. رحلة الدعوة تتبع رابطًا صادرًا من طابور اصطناعي مشفر، تختبر عدم تطابق التأكيد ثم القبول من النموذج، وتمنع إعادة استخدام الرمز مع حفظ الدور.

راجعت أيضًا بند معاينة البريد: handler المصدر المثبت نفسه يعيد metadata وbodyText فارغًا وbodyHtml/error بقيمة null، كما في مرجع الاستيراد القديم. الهدف يطابق هذا العقد باختبار MariaDB؛ لا توجد وظيفة معاينة كاملة في هذين المرجعين تحتاج إلى نقل. [تدقيق العقد وبصماته](evidence/reference-isolation/outbox-contract.json) يحسم ملاحظة المتابعة القديمة في tracking.md، ولا يعني كشف حمولة البريد المشفرة أو رموز الحسابات للواجهة.

## أكبر مستند قديم

حُسب الحجم لكل فرع محدود من مخططات الأنواع الـ27، مع الحقول الاختيارية والحدود القصوى للمصفوفات والنصوص والقيم المعدودة. محارف التحكم تحقق كلفة JSON القصوى: ستة بايتات لكل وحدة UTF-16؛ anchorId يخضع لحده ASCII. الأعداد الصحيحة محدودة، والاتحادات تختار أكبر بديل. أي نوع غير محدود أو قيد غير معروف يفشل الأداة بدل افتراض حد.

النوع الأكبر `servicesGrid`، وليس `columns` في العينة السابقة. أكبر مصفوفة مطبعة من 60 كتلة تبلغ **63,759,001 بايت لكل لغة**؛ نجح حفظ اللغتين معًا (**127,518,002 بايت**) والنشر وPageVersion وتطابقت البصمات. المصدر والهدف يعطيان ترتيب الأحجام نفسه. تستمر اختبارات 160MiB لجسم HTTP و300000 بايت لمغلف الشجرة وحد+1 و401 قبل تحليل الجسم و200/409 للتزامن. الاختبار على MariaDB حقيقية بمعامل packet 256MiB؛ لا يدعي اختبار خادم تشغيل فعلي.

## سجل الفشل وحدود الإثبات

التشغيل الكامل الأول بعد إضافة حالات تسجيل الدخول كشف 429 في رحلات لاحقة: تشترك جميع الحالات في loopback IP وحد 30 محاولة/10 دقائق. هذه حماية صحيحة وليست عيب محرر. fixture الحالات الجديدة يحفظ صف عداد الدخول قبل الحالة ويعيده بعد انتهائها في قاعدة اختبار معزولة، لتمنع التأثير على الحالات الأخرى؛ لا يغير limit أو runtime أو نتيجة HTTP ولا يضيف retries. اختبارات حصص المحاولات السلبية والتزامن تبقى مفعلة. سجل الفشل محفوظ محليًا وبصمته في checks.json.

كشف التشغيل التالي تراكم عناصر قائمة الاختبار: استعاد الاختبار القائمة عبر API الذي يعيد إنشاء المعرفات، ثم أدخل setup المعرفات الأصلية في تشغيل لاحق؛ تجاوزت القائمة حد 12 عنصرًا فرُفضت بـ400 كما ينبغي. أصلح cleanup ليستعيد صفوف القائمة نفسها ومعرفاتها داخل transaction ويتحقق من تطابقها. أعيد التحقق في قاعدة اختبار مستقلة جديدة دون مسح القاعدة السابقة، ثم أعيد التشغيل على القاعدة الجديدة نفسها لإثبات عدم التراكم. هذا تصحيح لعزل fixture، ولا يغير عقد حفظ القوائم في المنتج.

المصفوفة تحفظ نسخة قبل الإغلاق، وكل صف له مسار تنفيذ وملفات تحقق في acceptance-map.json. وصف verified-code يعني قبول الوظيفة المجرودة ضمن نطاق نقل الكود، لا برهانًا على جميع المدخلات الممكنة أو التشغيل الفعلي أو تغييرات مصدر مستقبلية. evidence القديم والاستيراد والنسب محفوظة، ولا تُحذف وظائف أو اختبارات لإغلاق الصفوف.

نتائج المجموعة النهائية وSHA الكود وCI تسجل في checks.json وطلب السحب؛ لا تُنسب نتيجة تشغيل سابق إلى commit لاحق.
