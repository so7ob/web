# خصوصية سجل البريد

حزمة W03a/Issue #14 وجزء EMAIL_DEV_MODE من #8. يُرسل نص الرسالة كاملًا إلى SMTP لكنه لا يُحفظ في EmailLog، سواء نجح الإرسال أو فشل أو كان وضع تطوير. السجل يبقي المستلم والموضوع والحالة والتاريخ؛ أخطاء المزود تتحول إلى رموز عامة ولا تُطبع. صندوق الصادر يعرض metadata فقط، ولا يجلب نصوص/HTML/أخطاء قديمة. فشل كتابة السجل بعد الإرسال لا يوصف كفشل تسليم كي لا يكون سببًا لإعادة إرسال تلقائية.

NODE_ENV=production يعطّل EMAIL_DEV_MODE برمجيًا؛ يجب ضبط SMTP للإرسال الحقيقي. في التطوير تبقى روابط API التجريبية للتطوير المحلي فقط، ولا تُخزن في outbox. لا تجعل بيئة التطوير متاحة للعامة. لم يُنفّذ اتصال SMTP حقيقي أثناء الاختبارات؛ استُخدم transport وهمي.

بعد أخذ نسخة خاصة متحققة وفق #11، يمكن لمسؤول التشغيل تنفيذ تنقية السجلات القديمة صراحة:

```bash
bun run scripts/redact-email-logs.ts --confirm-backup-and-redact
```

لا تُشغّل الأداة تلقائيًا مع build/start؛ عملية واحدة تزيل bodyText/bodyHtml/error وتحافظ على metadata. لا تطبع المحتويات. هذا PR لم ينفذها على قاعدة حقيقية. إزالة الحقول منطقيًا لا تضمن محوها من صفحات SQLite الحرة أو WAL أو backups القديمة؛ احمِ النسخ وحدد انتهاء احتفاظها وراجع الرموز النشطة التي ربما ظهرت سابقًا. لا تُبطِل كل جلسة أو رمز إنتاج تلقائيًا دون نطاق حادثة معتمد.

التراجع: لا تُعد سياسة حفظ/عرض الرموز الخام أو dev mode في الإنتاج. استعادة نصوص قديمة من نسخة احتياطية ليست تراجعًا مطلوبًا. يمكن إصلاح سلوك عرض metadata مع الحفاظ على حجب الحقول الخاصة. سكربت التنقية one-way ولا يتطلب تغيير schema.
